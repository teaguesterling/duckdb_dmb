# dmb v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A DuckDB v2.0.0 extension, `dmb`, that parses `.dcs` sheets and applies them to `duck_block[]` documents, with `dcs_rules`, `dcs_apply`, `dcs_explain` and `dcs_check`.

**Architecture:** Sheets parse with a **vendored** tree-sitter runtime and the tree-sitter-css grammar, called from C++. There is no runtime dependency on sitting_duck. A C++ selector compiler walks the tree-sitter selector subtree. A C++ matcher runs every rule over an in-memory block tree in one pass. Phases then rewrite the rows. `dcs_apply` is a scalar over one document (a `duck_block[]` list), the duck_block_utils convention.

**Tech Stack:** C++11 (DuckDB extension template, DuckDB v2.0.0 `v2.0-cyanoptera`), tree-sitter C runtime, tree-sitter-css v0.25.0 (generated `parser.c`), DuckDB's bundled RE2 for `:matches`, sqllogictest.

**Spec:** `docs/superpowers/specs/2026-11-13-dcs-design.md`. Brief: `docs/briefs/2026-11-13-build-dmb.md`.

## Global Constraints

- Target DuckDB **v2.0.0** (`d54cbbe3df`), submodule branch `v2.0-cyanoptera`, the same as duck_block_utils' v2.0 worktrees and sitting_duck.
- dmb will be statically linked into duckeye's Android engine: **no dependency that can't build for arm64-android.** tree-sitter is pure C (inferred to build; not yet measured on Android).
- **Symbol clash risk (inferred, unmeasured):** sitting_duck also links tree-sitter. A static link of both into one binary will have duplicate `ts_*` symbols. Pin the **same tree-sitter commit as sitting_duck** (`eaa10b279f208b47f65e77833d65763f072f3030`) so one copy can serve both later. Don't solve it now.
- Extension name `dmb`. SQL functions are prefixed `dcs_`. Property prefix `-dcs-`. Never register a name duck_block_utils registers (its spec, "Two extensions must not register the same function name"); in particular dmb does **not** register the `duck_block` type.
- The input document type is structural: `STRUCT(kind VARCHAR, element_type VARCHAR, content VARCHAR, level INTEGER, encoding VARCHAR, attributes MAP(VARCHAR, VARCHAR), element_order INTEGER)[]`. Bind rejects a list whose struct lacks any of these seven fields, by field name. Output type = input type.
- Errors never abort a document. Problems become diagnostics; `strict := true` turns them into errors.
- **Change implementation OR tests, never both at once.** Every task: test first, watch it fail, then implement.
- **Builds go through Slurm** (load the `slurm` skill first). Register with blq: `build` = `srun -n 1 -c 8 --mem=16G -p batch -t 60 make release GEN=ninja`; `test` = `srun -n 1 -c 4 --mem=8G -p batch -t 30 build/release/test/unittest "test/sql/*"`. Run the DuckDB CLI with `-no-agent`.
- Git through jetsam, on branch `feat/dmb-v1`. **No pushes, merges or releases without Teague's word.**
- Label claims measured or inferred. After each task lands, report to Teague and SendMessage `second-session` (find it with ListAgents).

## Review Focus

1. **A broken rule in the middle of a sheet.** tree-sitter's error recovery can swallow the rules after an ERROR (seen: `[a >= 2] {…}` followed by `#intro, code[…]` became ERROR). Expect: a diagnostic at the broken rule's line and column, and every rule tree-sitter still returns is applied. Task 3 measures how far the damage spreads and pins it.
2. **Non-ASCII text** in selectors, strings and headings (`"¶"`, `:contains("café")`, `# Zoë's notes`). Expect: code-point columns, `slug("Zoë's notes")` = `zoës-notes` (letters kept, apostrophe dropped). Tasks 3 and 5.
3. **A heading with inline children and a flattened `content`.** Expect `text()` = `content` for headings, else the concatenated inline descendants (duck_blocks spec, "A heading may carry BOTH…"). Task 4.
4. **An empty document, a NULL document, an empty sheet, a NULL sheet.** Expect: `[]` → `[]`; NULL blocks → NULL; empty sheet → input unchanged; NULL sheet → NULL. Task 5.
5. **`display: none` on a container.** Expect its whole subtree (inline children included) to go, and `element_order` renumbered 0..n-1 with no level jumps. Task 6.

## Shared interfaces (all in `namespace duckdb::dmb`)

```cpp
struct SourcePos { int32_t line = 0; int32_t column = 0; };               // 1-based, code points (D5)
struct Diagnostic { string severity; /* "error"|"warning" */ string code; string message; SourcePos pos; };
struct ValueToken { enum Kind { STRING, IDENT, NUMBER, FUNCTION }; Kind kind; string text; vector<ValueToken> args; };
struct Declaration { string property; string value_text; vector<ValueToken> tokens; bool important; int32_t order; SourcePos pos; };
struct Rule { int32_t index; string selector_text; ComplexSelector selector; string pseudo_element; // "", "before", "after"
              vector<Declaration> declarations; string media_format; SourcePos pos; };
struct Sheet { vector<Rule> rules; vector<Diagnostic> diagnostics; };
Sheet ParseSheet(const string &text);                                    // never throws on bad input

struct Specificity { int32_t a = 0, b = 0, c = 0; };                     // compared lexicographically
struct SimpleSelector { enum Kind { TYPE, UNIVERSAL, ID, CLASS, ATTR, PSEUDO_CLASS };
                        Kind kind; string name; string op; string value;  // op: "", "=", "~=", "^=", "$=", "*=", "|="
                        vector<ComplexSelector> args; string text_arg; int32_t a = 0, b = 0; };
struct Compound { vector<SimpleSelector> parts; };
struct ComplexSelector { vector<Compound> compounds; vector<char> combinators; // ' ', '>', '+', '~'; size = compounds-1
                         char leading = 0; /* relative selector in :has(> x) */ Specificity specificity; };

struct BlockNode { idx_t row; int64_t parent; vector<idx_t> children; string kind, element_type, content;
                   int32_t level; std::map<string,string> attributes; };
class BlockTree { public: static BlockTree FromList(const Value &list); vector<BlockNode> nodes;
                  bool Matchable(idx_t i) const; /* kind != 'inline' */ string Text(idx_t i) const; vector<string> Classes(idx_t i) const; };
bool Matches(const ComplexSelector &sel, const BlockTree &tree, idx_t node);

struct Change { int32_t element_order; int32_t rule; string property; string before; string after; };
struct ApplyResult { vector<Value> blocks; vector<Change> changes; vector<Diagnostic> diagnostics; };
ApplyResult Apply(const BlockTree &tree, const Sheet &sheet, const LogicalType &block_type);
```

`Change.element_order` is the block's order in the **input**. `before`/`after` are NULL-able strings rendered as text (`attributes['id']` value, `"removed"`, etc.).

### Task 3: `dcs_rules(sheet)` and the sheet parser

**Files:** Create `src/include/sheet.hpp`, `src/sheet_parser.cpp`, `src/include/selector.hpp`, `src/selector.cpp` (compile + specificity only; no matching), `src/functions.cpp`. Test: `test/sql/dcs_rules.test`.

**Interfaces:** Consumes `tree_sitter_css()`. Produces `ParseSheet`, `Sheet`, `Rule`, `Declaration`, `ComplexSelector`, `Specificity` (above), and the table function:

`dcs_rules(sheet VARCHAR)` → `rule INTEGER, selector VARCHAR, pseudo_element VARCHAR, property VARCHAR, value VARCHAR, important BOOLEAN, specificity INTEGER[], "order" INTEGER, media VARCHAR, line INTEGER, "column" INTEGER`. One row per (selector after list-splitting, declaration). `rule` is the index after splitting. `order` is the declaration's source order, shared by every selector of a list. `line`/`column` locate the declaration. `pseudo_element` is NULL when absent.

Approach: walk `stylesheet` children. `rule_set` → split `selectors` on its direct selector children (D-spec: "DCS splits comma lists itself"). `media_statement` with `feature_query (format: X)` → recurse with `media_format = X`; any other media query → warning `unsupported-media`. `import_statement` → warning `import-unsupported` (Task 8 adds it). `at_rule` `@frontmatter` → kept for Task 8, warning `not-yet` now. Any `ERROR` or `MISSING` node → diagnostic `syntax`, positioned at its start.

Selector compile rules: `tag_name` → TYPE (`h1`..`h6` stay TYPE; matcher interprets); `*` → UNIVERSAL; `id_selector` → ID; `class_selector` → CLASS; `attribute_selector` → ATTR (op from the operator token, value from source bytes with quotes stripped); `pseudo_class_selector` → PSEUDO_CLASS with `name` from `class_name`. Arguments: for `not`, `has` take the `arguments` children as selectors; for `section` re-parse the argument source text as `<text> {}` (D2); for `contains`, `matches` take the string content into `text_arg`; for `h`, `callout` take the bare token into `text_arg`; for `nth-child`, `nth-of-type` parse `an+b`, `odd`, `even` into `a`,`b`. Combinators from `descendant_selector`, `child_selector`, `sibling_selector` (`~`), `adjacent_sibling_selector` (`+`). An `arguments` node starting with a combinator (`:has(> img)`) sets `leading`. A pseudo-class name dmb doesn't know → diagnostic `unknown-pseudo-class` naming it; the rule is kept in `dcs_rules` but marked so Apply skips it (duckent: "refused by name, never an empty result").

Specificity: ID → a; CLASS, ATTR, PSEUDO_CLASS → b, **except** `:not()`/`:has()` contribute the maximum of their arguments instead; TYPE and a pseudo-element → c; UNIVERSAL → nothing. `:section(…)` counts as one pseudo-class, b+1, its argument not added.

### Task 4: The block tree and the matcher

**Files:** Create `src/include/block_tree.hpp`, `src/block_tree.cpp`, `src/include/matcher.hpp`, `src/matcher.cpp`; vendor `src/include/duck_block_vocabulary.hpp` from duck_block_utils `main`, byte-exact, with its provenance stamp (follow its "VENDORING THIS FILE" block). Test: `test/sql/dcs_match.test`.

**Interfaces:** Consumes `ComplexSelector`. Produces `BlockTree`, `Matches`, and a test-only scalar `dcs_select(blocks, selector VARCHAR) -> INTEGER[]`: the `element_order`s of matching blocks, ascending. (`dcs_select` stays public: it is the matcher's own surface, and Task 9's differential needs it.)

Tree: a node's parent is the nearest preceding row with a smaller `level`. `children` holds matchable children only. `Text(i)`: for a heading with non-empty `content`, `content`; otherwise the concatenation, in order, of `content` of every inline descendant; if it has none, `content`. `Classes(i)`: `attributes['class']` split on ASCII whitespace.

Semantics: TYPE matches `element_type`, with four HTML aliases the spec's examples use: `p` = `paragraph`, `img` = `image`, `li` = `list_item`, `pre` = `code` (an alias counts as a type for specificity); `h1`..`h6` match `element_type='heading'` with `heading_level` = n; `.x` via `Classes`; `#x` via `attributes['id']`; `[name]` reads `attributes[name]`, except `kind`, `encoding`, `element_type` which read the fields; `[level=…]` reads the `level` field. Structural pseudo-classes count matchable siblings only. `:root` = a matchable node with no matchable parent. `:empty` = no children of any kind and empty `content`. `:contains("s")` = `Text` contains `s` (case-sensitive). `:matches("re")` = RE2 partial match on `Text`; a bad pattern is a diagnostic at compile time and matches nothing. `:heading` = any heading; `:h(n)` = `hn`. `:section(sel)` = a heading matching `sel`, and every following node until the next heading with `heading_level` ≤ its own, or a node with a smaller `level`; descendants of included nodes included. Document-role pseudo-classes (`:meta`, `:chrome`, `:main`, `:data`, …) are Task 7.

### Task 5: `dcs_apply` with phase 1 (identity)

**Files:** Create `src/include/values.hpp`, `src/values.cpp`, `src/include/apply.hpp`, `src/apply.cpp`; modify `src/functions.cpp`. Test: `test/sql/dcs_apply_identity.test`.

**Interfaces:** Consumes `BlockTree`, `Matches`, `Sheet`. Produces `Apply`, `ApplyResult`, `Change`, `string Slug(const string &)`, `Value EvalValue(const Declaration &, const BlockTree &, idx_t node)` and the scalars `dcs_apply(blocks, sheet VARCHAR) -> same list type` and `dcs_apply(blocks, sheet VARCHAR, strict BOOLEAN)`.

Cascade: for each (node, property), the winning declaration is the max of `(important, specificity, order)`. **Match once**: phase-1 rules match the input; all later phases match the document after phase 1 (spec, "The cascade").

Phase 1 properties: `-dcs-id: <value>` sets `attributes['id']`; `-dcs-id: auto` sets it only where none exists, to `Slug(Text)` de-duplicated against ids already in the document (D6). `-dcs-class: +a -b c` adds `a` and `c`, removes `b`, keeps the existing order, writes space-joined (removing the key if empty). `--name: <value>` sets `attributes['name']`; `--name: unset` removes it. `--heading_level`, `--class`, `--id` are refused with diagnostic `reserved-attribute` and ignored. Values: strings concatenate; `attr(x)`, `text()`, `slug(<value>)`, `url()` (the document's `attributes['source']` on the root, else NULL; inferred, flag it). An unknown property or function → diagnostic `unknown-property` / `unknown-function`, ignored. `strict := true` raises the first diagnostic as an `InvalidInputException` with its line and column.
