# DCS type, DCS readers, and the table form of dcs_apply: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give dmb a registered `DCS` value type for a parsed sheet, with `dcs_sheet`, `dcs_format`, `read_dcs`,
`read_dcs_objects`, DCS input to `dcs_apply` and `dcs_explain`, and a table-in, table-out `dcs_apply`.

**Architecture:** One new unit, `dcs_value`, converts between dmb's internal `Sheet` and a DuckDB `Value` of
type `DCS`, both ways, and writes a value as `.dcs` text. Every function that takes a sheet binds the sheet
argument as `ANY`: a `LIST` is cast to `DCS` and converted; anything else is cast to `VARCHAR` and parsed. The
converter refuses what text cannot express and leaves every other check to the existing `CheckSheet` and
`Apply`, so text and `DCS` share one check path. The table form buffers all input rows in one thread and
writes the output in its final callback.

**Tech Stack:** C++17, DuckDB v2.0.1 extension API (submodule `8d78114e`), sqllogictest.

**Spec:** `docs/superpowers/specs/2026-11-18-dcs-type-design.md` (approved 2026-11-25).

**Decision from these, taken under fleet rules section 3 (reversible, recorded in the status note):** `DCS` is
registered **without an alias**, so a value can be queried with the list functions. The cost: `typeof` shows
the struct list, not `DCS`. `extra` is `JSON` (`LogicalType::JSON()`) on every platform.

## Interpretations (Claude's, recorded so a reviewer can reject them)

- **Text-level diagnostics** are every diagnostic `ParseSheet` emits except the ones selector compilation emits
  (`CompileSelectorNode`). So `empty-value` and `cannot parse declaration` are text-level: the parser drops that
  declaration, and `dcs_sheet` cannot hold it. Rule-level diagnostics are selector diagnostics, and every
  diagnostic `CheckSheet` and `Apply` emit.
- **Strict errors match** means the whole error message is equal, line and column included.
- **Split selector lists in a `DCS` value:** adjacent entries whose `declarations` lists are equal (every field,
  `extra` included) share declaration orders, as `Declaration::order` does for text. Text always produces such
  runs, so text and its `dcs_sheet` dedupe diagnostics the same way.
- **`rule` in `read_dcs`** is the 0-based position of the entry in the list. For plain rules this is the rule
  number of `dcs_rules` and `dcs_explain`, because the frontmatter entry is last.
- **Two `@frontmatter` blocks in text** become one frontmatter entry: text already merges them
  (`Sheet::frontmatter`), and a value with two frontmatter entries is refused.
- **NULL `filename` rows** in the table form are one document, written after every named document.

## Review Focus

1. A sheet with a bad selector that is not first on its line (`p { } h2:bogus { }`): the strict error must name the
   same column for text and for `DCS`. Task 2 owns the test.
2. A `DCS` value read back from Parquet, with no `DCS` name on its type, given to `dcs_apply`, `dcs_explain`,
   `dcs_format` and the table form. Tasks 2, 3, 6 own the tests.
3. A split list with a bad value (`h2, h3 { --x: attr(; }`): one diagnostic for text and one for `DCS`, not two.
   Task 2 owns the test.
4. The table form with `SET threads = 4`, more than 2048 rows, three files arriving interleaved. Task 6 owns it.
5. A non-ASCII selector (`h2:contains("é") , p:bogus`): positions count code points. Task 2 owns the test.

### Task 2: from a `DCS` value to a sheet; `dcs_apply` and `dcs_explain` take `DCS`

**Files:**
- Modify: `src/include/dcs_value.hpp`, `src/dcs_value.cpp`, `src/functions.cpp`, `src/selector.cpp`,

- Test: `test/sql/dcs_type_apply.test`
- Docs: `docs/reference.md` (`dcs_apply`, `dcs_explain`: "the sheet is text or DCS")

**Interfaces:**
- Consumes: `DcsType`, `SheetToDcs` (Task 1).
- Produces:
  - `Sheet DcsToSheet(const Value &dcs);` `dcs` has type `DcsType()`. Never throws on bad content: problems
    become `Sheet::diagnostics`.
  - `bool ReadExtra(const Value &extra, std::map<string, Value> &out, string &error);` parses a JSON object of
    scalars; nested values of unknown keys are skipped; false on text that is not a JSON object.
  - `bool CompileSelectorAt(const string &text, ComplexSelector &out, string &pseudo_element, vector<Diagnostic> &diagnostics, SourcePos origin);`
    as `CompileSelectorText`, but each diagnostic's position is the position inside `text`, moved to `origin`:
    on the first line of `text`, column = `origin.column + c - 1`; on later lines, the column is unchanged and
    the line is `origin.line + l - 1`. With `origin` = 0,0, every position is 0,0.
  - `Sheet SheetArgument(const Value &arg);` VARCHAR → `ParseSheet`, `DCS` → `DcsToSheet`. Used by every function
    that takes a sheet.
  - `void ResolveSheetArgument(ResolveScalarFunctionTypesInput &input, idx_t index);` sets argument `index` to
    `DcsType()` for a `LIST`, to `VARCHAR` for other non-NULL types.
- `dcs_apply` and `dcs_explain` overloads: the sheet parameter becomes `LogicalType::ANY`. The cache in `ApplyFun`
  and `ExplainFun` keys on `Value` equality, not on text.

`DcsToSheet` per entry, in list order:
- `meta` NULL: a rule. `index` counts these entries from 0. `selector` NULL → `syntax`, rule kept with
  `usable = false`. Compile `selector` (plus `"::" + pseudo_element` when `extra.pseudo_element` is set) with
  `CompileSelectorAt` at `extra.line/column`; false → `usable = false`. Keep `selector_text = selector`.
- `meta = 'frontmatter'`: its declarations go to `Sheet::frontmatter`. A second one, or one with `media`, →
  `syntax`, entry ignored. Any other `meta` → `syntax`, entry ignored.
- A declaration: `property` NULL or empty → `syntax`, declaration dropped. `value` that `TokenizeValue` rejects,
  or that holds a top-level `;` or `}`, or that ends in `!important` → `bad-value`, declaration dropped.
- `extra` that `ReadExtra` rejects, or a known key of the wrong JSON type → new code `bad-extra` (error), and the
  entry or declaration is used as if `extra` were NULL.
- Orders: one running counter over all declarations; an entry whose `declarations` equals the previous entry's
  reuses the previous entry's orders.
- A top-level comma in `selector` is already `selector-list` in `CompileSelectorText` (`selector.cpp:568`).

### Task 6: the table form of `dcs_apply`

**Files:**

- Test: `test/sql/dcs_apply_table.test`

**Interfaces:**
- Consumes: `SheetArgument`, `ResolveBlockFields`, `Apply`, `ThrowDiagnostic` (move it out of the anonymous

- Signature (one overload, measured above):

- Bind: output names and types = the input's. Build `LIST(STRUCT(input columns))` and pass it to

  as a struct `Value` to the local state, keyed by the `filename` column (or one key when there is none), and
  returns `NEED_MORE_INPUT` with an empty output. `in_out_function_final` sorts the keys (NULL last), sorts each
  document's rows by `element_order`, calls `Apply` once per document, and writes the rows a chunk at a time
  (`HAVE_MORE_OUTPUT` until the last).
