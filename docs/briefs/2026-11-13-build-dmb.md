## Measured facts (don't rediscover)

- **tree-sitter-css parses whole DCS sheets,** declarations included. sitting_duck's ast_select
  already parses selectors with `parse_ast_list_table(selector, 'css')` (css_selectors.sql:94). The
  ast-select-perf session ran parse_ast on DCS rules: `h2::after` became a pseudo_element_selector,
  `content` a declaration with string_value plus `attr(id)`, and `-cds-content-as: markdown` a
  declaration with plain_value.
- **Don't match through per-rule ast_select calls.** Its cost is planning, not execution: about
  16.7 s of planning against 0.125 s of execution, before a fix; 17.3 s → 2.3 s after
  decorrelating; PREPARE gives 18.1 s once, then 0.2 s per EXECUTE. DuckDB 2.0's planner is about
  20 times slower than v1.5 on that shape (duckdb/duckdb#26036). Hence a C++ matcher.
- **ast_select is coupled to read_ast's full schema** (a Binder Error when a column is dropped).
  sitting_duck spec 046 keeps that by design. Your matcher is your own, with 046's EXCEPT-both-ways
  differential against `ast_select_from` over blocks projected to the full schema (the duckeye CLI's
  projection, duckeye:2105) as the alignment check.
- **Selector lists `'A, B'` silently return 0 rows in ast_select** (sitting_duck#330). Split lists
  yourself, and keep lists out of the differential until #330 is fixed.
- **Ids by reader** (x86 p4: markdown v1.9.9, webbed 2.15.x; panduck reported by its own session):
  - Markdown headings get slug ids, but `{#id}` is broken (duckdb_markdown#111).
  - Panduck's org, LaTeX, DOCX and ODT headings get pandoc slug ids (since v0.10.0); RTF and EPUB
    are pending (duckdb_panduck#182).
  - HTML has explicit ids only (duckdb_webbed#275).
- **Classes:** duck_blocks uses `attributes['class']` today only on `section` blocks
  (duck_blocks_spec.md:264). Readers are being asked to fill it: duckdb_markdown#111,
  duckdb_webbed#275, duckdb_panduck#182.
- **Native table blocks and helpers exist,** merged in duck_block_utils:
  - #78 `duck_block_table_read`, with a constant argument;
  - #79 `duck_block_embedded_to_table` and `duck_blocks_parse_embedded`;
  - #82 `duck_blocks_sections`.
  `-dcs-as: table` on csv, json or tsv code blocks should call #79.
- **Reader-mode baseline** to beat, once reader mode is a sheet: median token F1 0.898 and 4-shingle
  F1 0.851, on 10 Readability.js pages (duckeye#28).

## Limits agreed up front

- **No pushes, merges, releases or community-extension PRs without Teague's word.** This repo was
  created private with one initial commit; work on branches after that.
- **Change implementation OR tests, never both at once.** New behaviour gets a test that fails first.
- **Batch work through Slurm** (the `slurm` skill). DuckDB extension builds are heavy: use
  `srun -n 1 -c 8 --mem=16G -p batch -t 60` or similar. Run the DuckDB 2.0 CLI with `-no-agent`.
- **Label claims measured or inferred.** Never write "production ready".
- **Target DuckDB v2.0.0**, the same as duck_block_utils and the duckeye engine. dmb will be
  statically linked into duckeye's Android engine later, so avoid dependencies that can't build for
  arm64-android, and say so if one is unavoidable.

## First question to settle with Teague

**How dmb gets tree-sitter-css.** The options:
- (a) vendor tree-sitter and the CSS grammar directly, as sitting_duck vendors its grammars. It's
  small and has no extension dependency.
- (b) require sitting_duck to be loaded, and call its `parse_ast`.
- (c) wait for sitting_duckling with only the CSS grammar (not started).

The spec leans (a), since full sitting_duck is about 15.8 MB in the Android engine.
